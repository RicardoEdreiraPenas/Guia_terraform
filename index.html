El flujo de trabajo de Terraform

01 📁
Escribir
.tf files
02 ⚡
Init
terraform init
03 ✔️
Validar
terraform validate
04 🔍
Plan
terraform plan
05 🚀
Apply
terraform apply
06 📤
Outputs
terraform output
07 🗑️
Destroy
terraform destroy
01
terraform init
Descarga providers y módulos. Ejecutar siempre al clonar o añadir un nuevo provider.
02
terraform plan
Muestra (+) recursos a crear, (~) a modificar y (-) a destruir. Tu mejor aliado.
03
terraform apply
Aplica los cambios. Pide confirmación interactiva antes de ejecutar.
04
terraform validate
Verifica la sintaxis HCL sin conectarse a ningún provider.
05
terraform fmt
Formatea el código al estilo oficial. Úsalo antes de cada commit.
06
terraform state list
Lista todos los recursos gestionados en el state actual.
07
terraform import
Importa un recurso existente en la nube al estado de Terraform.
08
terraform destroy
Destruye toda la infraestructura. ⚠️ Pide siempre confirmación explícita.
Módulo 03

Fundamentos de HCL

terraform {}
Versión requerida, backend remoto y providers necesarios.
provider {}
Configuración del provider (AWS, GCP, Azure). Region, credenciales, etc.
resource {}
El bloque principal. Define cada recurso cloud: VM, bucket, base de datos…
variable {}
Inputs parametrizables. Type, default y description obligatorios.
output {}
Valores exportados al finalizar. IP, ARNs, URLs accesibles vía CLI.
locals {}
Variables calculadas localmente. Evita repetición de expresiones complejas.
data {}
Consulta recursos ya existentes (sólo lectura). AMIs, VPCs, zonas DNS.
module {}
Instancia un módulo reutilizable local o del Terraform Registry.
main.tf · Ejemplo completo
# Configuración del provider
provider "aws" {
  region = var.aws_region
}

# Data source: busca la AMI más reciente
data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]
  filter {
    name   = "name"
    values = ["al2023-ami-*-x86_64"]
  }
}

# Recurso: instancia EC2
resource "aws_instance" "web" {
  ami           = data.aws_ami.amazon_linux.id
  instance_type = var.instance_type

  tags = {
    Name        = "${var.environment}-web-server"
    Environment = var.environment
    ManagedBy   = "Terraform"
  }
}

# Output: exponer la IP pública
output "public_ip" {
  description = "IP pública del servidor web"
  value       = aws_instance.web.public_ip
}
variables.tf · Tipos de variables
# string
variable "aws_region"   { type = string;  default = "us-east-1" }

# number
variable "instance_count" { type = number;  default = 1 }

# bool
variable "enable_https"   { type = bool;    default = true }

# list(string)
variable "azs"            { type = list(string); default = ["us-east-1a", "us-east-1b"] }

# map(string)
variable "tags"           { type = map(string);  default = { Env = "dev" } }

# Condicional ternario
instance_type = var.environment == "prod" ? "t3.large" : "t3.micro"
Módulo 06

Terraform State

📝
Archivos .tf
El estado DESEADO de la infraestructura que defines en código HCL
🗺️
terraform.tfstate
Mapa entre código y recursos reales. Terraform lo compara en cada plan
☁️
Infraestructura Real
Los recursos que realmente existen en AWS, GCP, Azure, etc.
providers.tf · Remote State en S3 (recomendado para equipos)
terraform {
  backend "s3" {
    bucket         = "mi-empresa-terraform-state"
    key            = "proyecto/terraform.tfstate"
    region         = "us-east-1"
    encrypt        = true
    dynamodb_table = "terraform-state-lock"   # ← previene escrituras simultáneas
  }
}
Módulo 07

Módulos Reutilizables

📁 modules/ └── 📁 ec2-instance/ ├── main.tf ← recursos ├── variables.tf ← inputs ├── outputs.tf ← exports └── README.md ← docs   📁 root/ ├── main.tf ├── variables.tf ├── outputs.tf └── providers.tf
main.tf · Instanciar módulo
module "web" {
  # Módulo local
  source        = "./modules/ec2-instance"
  name          = "web-prod"
  instance_type = "t3.medium"
}

module "vpc" {
  # Módulo del Registry
  source  = "terraform-aws-modules/vpc/aws"
  version = "5.0.0"
  name    = "mi-vpc"
  cidr    = "10.0.0.0/16"
}

Módulo 08

Construcciones Avanzadas

🔢
count
Crear N copias de un recurso
resource "aws_instance" "servers" {
  count         = 3
  instance_type = "t2.micro"
  tags = { Name = "server-${count.index}" }
}
# Acceso: aws_instance.servers[0].id
# Todos:  aws_instance.servers[*].id
🗂️
for_each
Crear recursos desde un mapa o set
resource "aws_s3_bucket" "storage" {
  for_each = {
    images  = "us-east-1"
    backups = "us-west-2"
  }
  bucket = "empresa-${each.key}"
}
# Acceso: aws_s3_bucket.storage["images"]
🔗
depends_on
Control explícito de dependencias
resource "aws_app" "backend" {
  # Espera a que la BD esté lista
  depends_on = [
    aws_db_instance.database
  ]
  # ... resto de config
}
⚙️
lifecycle
Controlar creación y destrucción
resource "aws_instance" "web" {
  lifecycle {
    # Crea nuevo antes de borrar el viejo
    create_before_destroy = true
    # Nunca destruir con terraform destroy
    prevent_destroy       = true
    # Ignorar cambios de tags en prod
    ignore_changes        = [tags]
  }
}
Módulo 10

Buenas Prácticas

01 📁
Estructura de archivos
  • main.tf para recursos principales
  • variables.tf siempre con description
  • outputs.tf para valores exportados
  • providers.tf separado del código
02 🔐
Seguridad
  • Nunca hardcodees credenciales
  • *.tfstate en .gitignore siempre
  • Usa variables de entorno o Vault
  • Activa cifrado en remote state
03 🏷️
Versionado
  • Fija versiones de providers: ~> 5.0
  • Commitea .terraform.lock.hcl
  • Usa tags de Git para releases
  • Semver en módulos internos
04 🧪
Testing
  • terraform validate en CI/CD
  • terraform plan en pull requests
  • Terratest para tests de integración
  • terraform test (nativo desde 1.6)
